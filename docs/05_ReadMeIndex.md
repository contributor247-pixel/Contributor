# 05 — Read Me / Index

This `docs/` folder is the complete documentation set for building the **Contributor**. Hand these files to Claude Code as described below — do not skip around, the order matters.

## What each file is for

| File | Purpose |
|---|---|
| **00_ScopeDocument.md** | The canonical source of truth: roles, permissions, content model, revenue splits, subscription structure, collaboration workflow, admin capabilities, third-party services, the 5 key user flows, out-of-scope items, and the decisions already made (Stripe, Auth.js + Neon, Drizzle). Every other doc points back to this one. |
| **01_ApplicationFlow.md** | The end-to-end map of every role's journey through the app, as ten numbered flows (A–J) with a mermaid diagram each. Used to build features correctly and to QA the whole app at the end. |
| **02_ThemeGuideline.md** | The full visual design system: colors, type, spacing, components, motion, and responsive rules — extracted from the `Refrence/` screenshots and elevated to "ultra polished" editorial-magazine quality. |
| **03_FolderStructure.md** | The exact Next.js App Router project structure this build follows, with reasoning per folder and naming conventions. |
| **07_ComponentArchitectureAndStandards.md** | The engineering/reuse discipline layer: which shared components must never be duplicated per-page, TypeScript/component/data-fetching/validation coding standards, and what "tested" means at the component level. Sits alongside 00/02/03 as a fourth "how we build" reference. |
| **04_MasterBuildGuide.md** | The step-by-step build plan — Step 0 (account/environment setup) through Step 17 (production deploy), plus final verification/test-case prompts. Every step is ready to paste into Claude Code. |
| **05_ReadMeIndex.md** | This file. |
| **06_ProjectState.md** | The **live build tracker** — updated by the coding agent after every step. Records what's done, what's next, and every "your choice, document which" decision made along the way. This is what lets you switch to a different agent session, a different model, or come back after a break with zero lost context — a new agent reads this file first and resumes exactly where the last one left off. Starts empty/"Step 0" and fills in as the build progresses — you don't write to it yourself, just glance at it if you want a status snapshot. |

## Recommended reading/usage order

1. Read **00_ScopeDocument.md** first, yourself, once — even though you're not a coder, understanding the roles and revenue splits will help you sanity-check what Claude Code builds.
2. Skim **01_ApplicationFlow.md** and **02_ThemeGuideline.md** to get a feel for how the app behaves and looks — you don't need to memorize them, Claude Code will re-read them at each relevant step.
3. Glance at **03_FolderStructure.md** just so the project layout isn't a surprise when you look at your file explorer later, then **07_ComponentArchitectureAndStandards.md** so you understand why Claude Code will keep referring back to "the existing Navbar/ArticleCard/etc." instead of building a new one each time.
4. Open **04_MasterBuildGuide.md** and start at **Step 0** — this is the document you'll actually work through, top to bottom, pasting each "Agent Task" block into Claude Code and completing each "Manual Task" yourself, testing after every step before moving to the next.
5. At the end of Step 17, run the five prompts in **04_MasterBuildGuide.md**'s "Verification & Test-Case Prompts" section (3 hardening/QA prompts + a scope completeness audit + a whole-app-flow walkthrough) to harden and audit the finished build.
6. If you ever switch to a new Claude Code session, hit usage limits and continue later, or want to try a different model partway through — don't worry, don't re-explain anything, and don't re-paste old context. Just open a fresh session, point it at the project, and say "resume the build" (or similar) — the guide's own resume instructions send it straight to `06_ProjectState.md` to pick up exactly where the last session left off.

## Non-negotiables (keep these in mind at every step)

**Sequence matters enormously** — steps in `04_MasterBuildGuide.md` must be run in order; each one depends on the ones before it (database before auth, auth before role-gated routes, roles before monetization, monetization before payouts, core CRUD before polish/animation, polish before final QA). Every "Agent Task" prompt is written to re-read `00_ScopeDocument.md`, `02_ThemeGuideline.md`, `01_ApplicationFlow.md`, and — for component-heavy steps — `07_ComponentArchitectureAndStandards.md`, rather than re-deriving rules from scratch, so the numbers (roles, revenue splits, plan names) and the component reuse rules never drift between steps. **Reusable-component discipline is a non-negotiable:** shared UI (Navbar, Footer, ArticleCard, AuthModal, SearchOverlay, buttons/inputs/modals, dashboard shell, loading/empty/error state components) is built once per `07_ComponentArchitectureAndStandards.md` and imported everywhere — never duplicated per page or per dashboard role. The visual bar is "ultra polished, premium, editorial magazine" — never generic SaaS or default shadcn styling — and every UI step must explicitly deliver both full mobile-first responsiveness and a deliberate motion/animation layer, not just static layout. Every step also follows the same **4-phase loop** (Build → Test → Bug-Find & Gap-Find → Fix & Re-test) defined once in `04_MasterBuildGuide.md`'s "How to use this document" section — a step isn't done just because its Testing checklist passed. Always respect the **Agent Task vs. Manual Task** split: Agent Tasks are pasted into Claude Code, Manual Tasks (dashboard clicks in GitHub, Vercel, Neon, Stripe, Resend, DNS) are things only you can do — do them exactly when the guide tells you to, not before, not after. Finally, **`06_ProjectState.md` must be kept current after every step** — this is what makes the build safely resumable across sessions, agent restarts, and even different models, so never skip that update even when a step feels small.
